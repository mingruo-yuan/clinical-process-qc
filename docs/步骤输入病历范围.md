# 各功能(流程步骤)输入病历范围说明

系统模拟患者入院全流程，每个功能只向 LLM 提供**该时点应有的病历章节**（模拟入院 → 检查 → 术前 → 术后 → 出院），防止"提前看到未来信息"（如术前建议看到手术记录）。

裁剪规则代码位置：`utils/data_loader.py`
- `STEP_GROUPS`：章节按临床时点分组（core / preop_reports / lab / frontsheet_only / postop）
- `STEP_INPUT_SCOPE`：每个流程步骤使用哪些分组
- `FIELD_MASKS`：个别章节做字段级裁剪（如诊断章节术前只暴露"入院诊断"）

---

## 章节分组

| 分组 | 章节 |
|---|---|
| core（入院即存在） | 诊断、入院记录、NRS入院评估、自理能力评估、长期医嘱单、临时医嘱单 |
| preop_reports（入院初检查） | 电子喉镜、CT、电子胃镜、超声、超声心动图、心电图、常规通气功能 |
| lab | 化验单 |
| frontsheet_only | 病案首页 |
| postop（术后才产生） | 手术记录、麻醉记录单、术后病程、病理检查报告单、术后护理记录（术日/术后一日）、手术风险评估表、VTE评分、NRS术后评估、PACU记录单 |

---

## 各功能输入章节

| 功能(技能) | 步骤 | 输入章节 |
|---|---|---|
| S02 诊断检测 | admission | core（诊断仅保留"入院诊断"） |
| S03 医嘱遗漏检测 | admission_order | core + preop_reports + lab + 病案首页（仅保留"入院日期"） |
| S04 鉴别诊断 | first_record | core（诊断仅保留"入院诊断"）+ preop_reports |
| S05 手术指征评估 | supplement | core（诊断仅保留"入院诊断"）+ preop_reports + lab |
| S06 手术建议 | preop | core（诊断仅保留"入院诊断"）+ preop_reports + lab |
| S07 术后治疗指征 | postop | core + preop_reports + lab + postop |
| S08 出院建议 | discharge | 全量 |
| S09 病案首页质控 | frontsheet | 全量 |

---

## 字段级裁剪（FIELD_MASKS）

| 章节 | 步骤 | 仅保留字段 |
|---|---|---|
| 诊断 | admission / first_record / supplement / preop | 入院诊断（**不暴露出院诊断**） |
| 病案首页 | admission_order | 入院日期（**不暴露出院日期等**） |

---

## 常见问题

**问：为什么手术建议(S06)里没有手术记录？**
手术记录属于 `postop` 分组（术后才产生）。S06 对应 `preop` 步骤，只输入 core + preop_reports + lab，即诊断、入院记录、医嘱、检查报告、化验单。这是刻意设计——术前讨论时手术尚未发生，不能用术后信息来"作弊"。

**问：为什么诊断章节术前只有"入院诊断"？**
诊断章节同时含"入院诊断"和"出院诊断"。出院诊断是出院时才确定的，术前步骤（admission/first_record/supplement/preop）只看得到入院诊断；只有出院(S08)、病案首页(S09)步骤才用全量。

**问：S03 为什么单独给了病案首页？**
S03 做"检查检验时效性"核查，需要"入院日期"计算各检查距入院天数，所以额外注入病案首页（仅入院日期字段）。
